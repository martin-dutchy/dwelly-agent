# Agent observability and eval tools: how they present runs, traces and eval results

Scope: LangSmith, Langfuse, Arize Phoenix/AX, Braintrust, W&B Weave, AgentOps, Datadog LLM Obs, OpenAI Agents SDK traces, Anthropic Console, Galileo, Patronus, Lakera, PostHog (bonus). Research date 10 Oct 2026. Several products were found only via docs/marketing; no direct screenshots were inspected. Helicone and Humanloop were not researched in depth (see Gaps).

## (a) How a single trace/run is presented: tree vs timeline vs transcript vs graph

### Takeaway
Every major tool converged on the same arrangement: a run list, then a split pane with a navigator on the left (span tree, timeline/waterfall or graph) and a detail panel on the right (input/output/metadata of the selected step). The biggest 2025-2026 shift is toward *multiple equal views of the same run* (tree, timeline, graph, flat log, transcript), with "see the shape first, then zoom" as the explicit design goal. For long agent runs, vendors added flat logs and transcript views because nested trees got noisy.

### Cited Findings
- **Langfuse, timeline (Jun 2024):** a timeline chart was added to show where agent runs lag and which steps run in parallel. — [Langfuse changelog 2024-06-12](https://langfuse.com/changelog/2024-06-12-timeline-view)
- **Langfuse, new trace view (19 Mar 2025):** a toggle between chronological (timeline) and hierarchical (tree) layouts with equal metrics and scores in both; view settings to show or hide scores, comments and metrics and to turn colour coding on or off; search observations by type, ID or name. — [Langfuse changelog 2025-03-19](https://langfuse.com/changelog/2025-03-19-new-trace-view)
- **Langfuse, graph view:** a LangGraph graph view (beta, Feb 2025). Graph view modes (13 Jul 2026): an *Aggregated* mode collapses same-named steps into one node with a counter and draws loops as cycles; an *Expanded* mode gives every call its own node and unrolls loops into a DAG in execution order. The layout is stable each time a trace opens. — [Langfuse changelog 2025-02-14](https://langfuse.com/changelog/2025-02-14-trace-graph-view.md), [Langfuse changelog 2026-07-13](https://langfuse.com/changelog/2026-07-13-graph-view-modes)
- **Langfuse, Agent Graphs plus a flat "Trace Log View" (reportedly Nov 2025):** the log view gives a flat stream of agent steps for workflows that loop or branch heavily. — [Mastra comparison](https://mastra.ai/articles/langfuse-vs-langsmith) (secondary source)
- **Langfuse, Responsive Timeline (28 Aug 2026):** fits the whole trace on screen on both axes. Rows shrink to single lines, with colour encoding the observation type so fan-outs and long generations are visible as "terrain." Scroll pans; pinch or ⌘-scroll zooms; double-click zooms to a step and shows its labels again; drag selects a time range; a "Fit" control returns to the full trace. Labels appear only when there is room. The same renderer works in the side peek and on a phone. The stated rationale: the old version made you scroll "hoping to recognise the part that mattered", and the goal is to see "the shape of the run first, then zoom in". — [Langfuse changelog 2026-08-28](https://langfuse.com/changelog/2026-08-28-responsive-timeline)
- **LangSmith:** a Details view per run (inputs, outputs, metadata, timing, errors, child runs). A Threads tab plus a "Turns" view, where each turn is a card with the root run's input and output (needs `thread_id` metadata). Feedback can be attached to any intermediate span, not just the root. — [LangSmith view traces](https://docs.langchain.com/langsmith/view-traces), [LangSmith annotate inline](https://docs.langchain.com/langsmith/annotate-traces-inline)
- **AgentOps:** a "Session Waterfall" with a time visualisation on the left of LLM calls, Action events, Tool calls and **Errors as their own event type**, and the selected event's prompt and completion on the right. A session drilldown shows LLM calls "as a familiar chat history view" plus charts of event types and durations. — [AgentOps dashboard docs](https://docs.agentops.ai/v2/usage/dashboard-info), [AgentOps v1 docs](https://docs.agentops.ai/v1/)
- **Datadog LLM Observability:** an execution-flow graph showing handoffs and the relationships between LLM calls, tool calls and agents. The trace header shows total tokens, number of LLM calls, models used and estimated cost; selecting a span narrows to its input, output and metadata. — [CrewAI docs: Datadog](https://docs.crewai.com/en/observability/datadog), [Datadog blog](https://datadoghq.com/blog/monitor-ai-agents)
- **OpenAI Agents SDK Traces dashboard:** each run is a `trace()`. Guardrails get a `guardrail_span` and handoffs a `handoff_span`, so policy checks appear as first-class nodes in the span tree. A secondary source says guardrail spans record the guardrail name and tripwire status. — [OpenAI Agents SDK tracing](https://openai.github.io/openai-agents-python/tracing/), [secondary guide](https://claw.aguidetocloud.com/openai/agents-sdk/tracing/)
- **Arize AX (Observe 2025):** an "Agents" tab renders agent runs as an interactive flowchart, and clicking a node shows its span data. It is unclear whether open-source Phoenix has this. — [Arize Observe 2025 releases](https://arize.com/blog/observe-2025-releases/)
- **Galileo Graph View:** renders every branch, decision and tool call. An "Insights" panel inside the graph says what went wrong, why, and what to do next, with links to the exact trace or span (July 2025). — [Galileo agent reliability](https://galileo.ai/agent-reliability), [Galileo blog Jul 2025](https://galileo.ai/blog/galileo-agent-reliability-platform)
- **Braintrust trace panel:** input, output, expected, metadata, span hierarchy, scores *with explanations*, and timing and tokens. It has fullscreen and "open in page" buttons, plus Timeline and Thread view options. — [Braintrust interpret results](https://www.braintrust.dev/docs/guides/evals/interpret)

### Inferences
- For a case-worker console: give a one-line-per-event chronological log as the default (like Langfuse's Trace Log View and AgentOps' waterfall with Errors as a first-class event type), with the raw input and output in a side panel on demand. Nested span trees are an engineer view.
- Treat policy denials the way OpenAI treats guardrails: as their own span or event type with name and outcome ("denied by rule X"), never buried in a tool output.
- Colour-coded event types plus "fit whole run then zoom" (Langfuse 2026) is a good model for showing a 20-80 step case at a glance.
- Langfuse's aggregated graph mode (repeated steps collapsed with a counter) suggests collapsing repeated read-back or retry loops into "3 attempts" chips.

### Gaps
- No primary-source screenshots of the OpenAI Traces dashboard UI layout. Helicone's trace UI was not researched (one vendor article calls its span-level debugging "limited", [MLflow article](https://mlflow.org/articles/llm-observability-with-the-best-ui-a-2026-engineers-guide/), which is competitor content).
- How these tools style a *failed write* versus a model error was not documented beyond "error" status.

## (b) How eval/experiment results are presented across many test cases

### Takeaway
Braintrust is the reference design: a table of cases with per-scorer columns whose headers carry the summary stats, a baseline-relative delta column (green and red), "order by regressions", saved views such as "Errors" and "Unreviewed", group-by on classifier labels, and one click from an aggregate card to the filtered failing rows and then to the trace. Weave adds a side-by-side scorecard with radar and bar charts. Failure clustering is moving to LLM-generated categories (Braintrust Loop and Topics, Patronus taxonomy, PostHog clusters, Galileo Insights).

### Cited Findings
- **Braintrust layouts:** List, Grid (outputs side by side), Summary (large-type score cards) and Summary table (scores as rows, experiments as columns, PDF download). Column headers show summary statistics per score. A row-type chip switches between Traces and Spans. — [Braintrust interpret results](https://www.braintrust.dev/docs/guides/evals/interpret)
- **Braintrust built-in views (Layers menu):** Default, Non-errors, Errors, Scorer errors, Unreviewed, Assigned to me, plus custom saved views. The filter bar accepts point-and-click, SQL or natural language. — [Braintrust interpret results](https://www.braintrust.dev/docs/guides/evals/interpret), [Braintrust compare experiments](https://www.braintrust.dev/docs/evaluate/compare-experiments)
- **Braintrust baseline comparison:** cases are matched by `input` (a custom comparison key is possible). Each row gets a score delta, green for improvement and red for regression. The baseline defaults to the latest experiment on the same git branch. — [Braintrust compare experiments](https://www.braintrust.dev/docs/evaluate/compare-experiments)
- **Braintrust from aggregate to case:** clicking a summary card or a header score opens a menu with the aggregate value, the delta vs base, and filters for "X regressions", "X improvements" or matching rows. Display > Columns has "Order by regressions". The Summary table has a "Comparison grade" row (Improvement, Regression, Tradeoff or Tie). — [Braintrust compare experiments](https://www.braintrust.dev/docs/evaluate/compare-experiments)
- **Braintrust Diff mode:** sub-modes Base→Comparison, Comparison→Base and Expected→Output; a character-level diff in the detail panel; a side-by-side option; capped at 4,096 characters per field. Timeline and Thread views are disabled while it is on. — [Braintrust compare experiments](https://www.braintrust.dev/docs/evaluate/compare-experiments), [interpret](https://www.braintrust.dev/docs/guides/evals/interpret)
- **Braintrust failure grouping:** classifier columns (`classifications.*`) are sortable, filterable and groupable. "Topics" facet columns show which input types do worse. "Loop" summarises results, categorises errors and explains score drops. Rows can be assigned to teammates for review, and a permalink uses the experiment ID. — [Braintrust interpret results](https://www.braintrust.dev/docs/guides/evals/interpret)
- **W&B Weave Compare evaluations (2024):** select two or more evals and click Compare. It shows summary radar and bar plots over user scores plus latency and tokens, a model scorecard, a baseline setting, and per-example outputs side by side. Leaderboards have one column per (evaluation, scorer). — [Weave compare evals](https://docs.wandb.ai/weave/guides/evaluation/compare_evals), [W&B announcement](https://wandb.ai/wandb_fc/product-announcements-fc/reports/Announcing-New-evaluation-comparisons-in-W-B-Weave--Vmlldzo4NjUyNDcy), [Weave leaderboards](https://docs.wandb.ai/weave/guides/core-types/leaderboards)
- **Anthropic Console Evaluate tab (Jul 2024):** a grid of test cases (manual, CSV or "Generate Test Case"), "Run all", side-by-side comparison of two or more prompt versions, and human grading on a 5-point scale. Grading is manual, with no automated scoring. — [Anthropic news](https://www.anthropic.com/news/evaluate-prompts), [Anthropic eval tool docs](https://docs.anthropic.com/en/docs/test-and-evaluate/eval-tool)
- **Patronus Percival:** an "Analyze with Percival" button on a trace; a Taxonomy tab under Traces showing a base error taxonomy (reasoning, system execution, planning and coordination errors; 20+ failure modes) that users extend with "Define New"; similar errors are grouped; "Percival Chat" answers questions about a trace. — [Patronus error taxonomy](https://docs.patronus.ai/docs/percival/error-taxonomy), [custom taxonomy](https://docs.patronus.ai/docs/guides/workflows/custom-error-taxonomy), [Percival overview](https://docs.patronus.ai/docs/percival/percival)
- **PostHog trace clustering (11 Mar 2026):** an LLM summarises sampled traces, which are embedded and clustered (HDBSCAN). A "Clusters" tab shows a 2-D scatter coloured by cluster, a bar chart of cluster sizes with LLM-written labels, an "Outliers" noise group, and drill-down to individual traces plus their summaries. — [PostHog blog](https://posthog.com/blog/llm-analytics-clustering-how-it-works.md)
- **Galileo agentic metrics:** tool error rate, tool selection quality, action advancement and action completion. The Insights Engine identifies failure modes with root cause tied to exact traces. — [Galileo blog Jul 2025](https://galileo.ai/blog/galileo-agent-reliability-platform)

### Inferences
- For 50 cases: a top row of 3-4 score cards (pass rate, mean score, critical failures, "stopped short" count), each clickable to a filtered case table; a case table with an outcome column, per-dimension score columns with header stats, a "stop reason" classifier column you can group by, and a delta-vs-previous-run column if a baseline exists; and a row click opening the case timeline. This mirrors Braintrust's Summary → filter → trace flow.
- Stop reasons should be a fixed, small taxonomy (like Patronus categories) rather than free text, so they can be grouped and counted. LLM-written cluster labels are optional polish.
- Built-in views like "Errors" and "Unreviewed" are cheap and very useful presets.

### Gaps
- Few tools document a *score distribution histogram*. Braintrust uses header stats rather than histograms, per its docs.
- The Phoenix experiment comparison UI status was unclear (a community post said comparison views were "still on the docket", undated). — [Arize community](https://community.arize.com/x/arize-news/msg_MdxmpOR71lhl/inquiry-about-longitudinal-framework-in-phoenix-do)
- Humanloop's eval UI was not researched.

## (c) Human review, non-engineer summaries, guardrail surfacing, and what practitioners praise or complain about

### Takeaway
For non-engineers, vendors lean on *session replay as a transcript* plus keyboard-driven annotation queues, and increasingly on AI summaries ("Insights", "Loop", "Percival Chat", "Ask AI" filters). Complaints centre on raw JSON blobs, deeply nested or broken trace trees, and having to scroll huge traces. Some practitioners argue that generic tools lose to small custom review UIs built for the domain. Guardrail products show a list of requests with a "Detections" filter plus request detail; they flag, and the app decides whether to block.

### Cited Findings
- **Langfuse for product teams:** session replay reads "top to bottom like a transcript", and you open any turn to see what happened behind it. A sessions table shows score aggregates per session (for example a "resolution" score). There are saved views with permalinks, keyboard-shortcut scoring in annotation queues, and "Ask AI" builds filters from plain language "without knowing the field names". The Member role can score but not configure. — [Langfuse for product teams](https://langfuse.com/resources/engineering/langfuse-for-product-teams)
- **Langfuse annotation queues:** domain experts add scores, comments and corrected outputs to traces, observations or sessions (session-level support since Jul 2025). Score configs standardise the criteria. — [Langfuse annotation queues](https://langfuse.com/docs/evaluation/evaluation-methods/annotation-queues), [changelog 2025-07-28](https://langfuse.com/changelog/2025-07-28-sessions-in-annotation-queues)
- **LangSmith annotation queues:** route interesting runs to annotators to grade against criteria. Inline notes come from a run's three-dot menu. — [LangSmith user guide](https://docs.smith.langchain.com/user_guide), [annotate inline](https://docs.langchain.com/langsmith/annotate-traces-inline)
- **Braintrust:** "Assign" rows to teammates; an "Unreviewed" and "Assigned to me" view. — [Braintrust interpret](https://www.braintrust.dev/docs/guides/evals/interpret)
- **Lakera Guard:** the Dashboard shows analytics by time range and project. The Requests page lists every screening with checks, results, latency and region. A "Detections" tab filters to flagged requests only; request detail shows the screened content, the checks run, the result and the raw API response. Lakera only *flags*, and the app decides whether to block. — [Lakera platform docs](https://docs.lakera.ai/docs/platform), [Lakera policies](https://docs.lakera.ai/docs/policies)
- **Complaint, raw JSON:** PostHog calls raw traces "a bag of JSON" whose structure varies by provider and framework. It re-renders traces as a line-numbered ASCII tree before summarising, because metadata distracts. — [PostHog blog](https://posthog.com/blog/llm-analytics-clustering-how-it-works.md)
- **Complaint, broken or nested trees:** a competitor's article claims Langfuse had nested-span rendering bugs causing "overlapping and unusable trace trees", and that UIs which flatten trees or break expand/collapse "destroy debugging speed". This is vendor-biased (MLflow). — [MLflow article](https://mlflow.org/articles/llm-observability-with-the-best-ui-a-2026-engineers-guide/)
- **Complaint, scrolling big traces:** Langfuse's own rationale for the 2026 timeline is that users had to scroll through traces "hoping to recognise the part that mattered". — [Langfuse changelog 2026-08-28](https://langfuse.com/changelog/2026-08-28-responsive-timeline)
- **Praise for a polished tree:** a hands-on comparison says LangSmith's trace tree is "easier to navigate with more intuitive filtering" than Langfuse's (one author's view). — [Mastra comparison](https://mastra.ai/articles/langfuse-vs-langsmith)
- **Custom review tools:** Hamel Husain's evals FAQ reportedly recommends building custom annotation tools, which pull context from several systems, render data the way the domain needs, and use keyboard navigation, over generic tools. The claim of 10x faster iteration comes from a secondary summary and is unverified. — [secondary summary](https://marketnews.xskill.com/a/7305?m=en)
- **AI summary for the run:** Galileo shows session-level summaries and concrete fixes linked to spans. Patronus "Generate Insights" was used by Weaviate to read long agent traces that would otherwise take hours. — [Galileo agent reliability](https://galileo.ai/agent-reliability), [Patronus Weaviate case study](https://patronus.ai/case-studies/weaviate-leverages-patronus-percival-to-accelerate-complex-ai-agent-development)

### Inferences
- An ops lead needs a transcript or narrative view (the Langfuse session replay pattern) in domain language: "Agent asked tenant for photos → booked contractor (confirmed by read-back) → write to calendar failed → escalated to Jan". Spans and JSON go behind a "details" toggle.
- Human decisions belong in the same timeline as agent events, with an explicit "waiting on human" state. This is the equivalent of annotation-queue "Assigned to me" and "Unreviewed" views applied to live cases.
- Show policy denials Lakera-style: their own filterable event type ("Denied by policy"), naming the rule, with the attempted action visible, kept separate from errors.
- Distinguish confirmed outcomes from claimed ones. No vendor found documents a "verified by read-back" badge, so this would be a differentiator rather than a copied pattern.

### Gaps
- No primary Hacker News or Reddit threads were found that criticise trace UIs. The complaint evidence comes from vendor blogs, so treat it as directional.
- NeMo Guardrails and Guardrails AI dashboards, Helicone sessions and Humanloop review UI were not covered within the tool-call budget.
- No vendor was found offering a true natural-language "narrative" of a run aimed at non-engineers beyond AI insight panels (Galileo, Patronus, Braintrust Loop) and transcript-style session replay.
