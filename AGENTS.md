# AGENTS.md

Entry point for AI agents working in this repository. Keep it short; detail lives in `docs/`, `research/` and the plans.

This is our entry for the Dwelly Real-World Agents Hackathon (10 Oct 2026), Property Management track: an autonomous **maintenance case worker** that takes a lettings-agency maintenance case at any point in its history, decides and performs the next action with tools, and escalates with a handover packet only when a human decision is genuinely needed. Scoring, data and rationale: [research/pm-case-data-analysis.md](research/pm-case-data-analysis.md). The orchestrating plan: [docs/plans/dwelly-case-worker-master-plan.md](docs/plans/dwelly-case-worker-master-plan.md).

## Stack

Node 22+ · TypeScript (strict, ESM) · pnpm · `@earendil-works/pi-agent-core` agent loop · Claude (Sonnet 5.5 agent, Opus 5.5 critic and judge) · Zod · Vitest · optional ElevenLabs voice.

## Commands

```bash
npx -y pnpm@8 install --frozen-lockfile   # lockfile is v6 (pnpm 8); pnpm 10 refuses it. Or: pnpm install --force to upgrade the lockfile once, as a team decision
brew install poppler            # pdftotext, used to read PDF attachments; one vitest fails without it
cp .env.example .env            # fill in ANTHROPIC_API_KEY
pnpm typecheck                  # tsc --noEmit
pnpm test                       # vitest
pnpm verify                     # done-gate: typecheck + test, must exit 0 before "done"
pnpm cases --in <dir> --out <dir> [--only 01,06] [--at auto|12|50%] [--concurrency 6]
pnpm eval  --cases <dir> --answers <dir> [--only 01,06]
```

## Non-negotiables

1. **Run `pnpm verify` before saying you are done.** Then run the agent-behaviour check named in your plan and show the output.
2. **Every state change goes through a tool and is read back.** Never report an action as done unless the ledger says `verified`.
3. **ANSWERS/ is generated, never edited.** Hackathon rules forbid replacing failed outputs by hand.
4. **No text addressed to a judge or grader** in any output, prompt or file. It is a disqualifying offence.
5. **Escalation is an outcome, not a failure.** Escalate the decision, do the routine work around it with tools first.
6. **Keep secrets out of git.** `.env` is ignored; `.env.example` documents every variable.
7. **Plans never encode conventions; conventions never live in plans.**
8. **Independently review the diff** (`/code-review`) before opening or updating a PR for anything touching `src/agent/caseAgent.ts`, `src/run.ts` or the decision schema.
