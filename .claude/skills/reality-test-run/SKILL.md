# Reality Test run

Rules: §4, §5, §6C/D, §7, §13 and §16. **The results must be generated by the submitted system. Never hand-edit or replace an agent output** (doing so fabricates results and can zero the component or disqualify the team). The code is already frozen at 16:30, so don't change the implementation in this window. If the runner crashes on a case, re-running the same code is fine. Patching the code is not.

## Before 16:30 (rehearse at least once)

- `.env` is filled in, and `pnpm typecheck && pnpm test` pass.
- The code and demo video are committed and pushed, and the hash is noted (the 16:30 form).
- Time a full practice batch to confirm that N cases fit in about 15 minutes. Adjust `--concurrency`, keeping rate limits in mind (`LLM_CONCURRENCY`).
- Confirm that `src/agent/cases.ts` / `publicCases.ts` can load an unfamiliar folder layout. If the released format is different, the only acceptable fix is a loader-only adapter committed **before** 16:30. Otherwise, run as-is.

## At 16:30

1. Note the start time. Unpack the cases (organisers call the folder `HackatonChallendges/`) and inspect the layout: `ls`, one `index.md`. Don't read cases in order to steer the agent.
2. Run everything in one go:
   ```bash
   pnpm cases --in "<released cases dir>" --out ANSWERS 2>&1 | tee ANSWERS/run.log
   ```
   (Create `ANSWERS/` first if `tee` needs it.) For a public-format layout with full history, use `--at` only if the task asks for a decision at a specific point.
3. If some cases errored or timed out, re-run only those with `--only <ids>`, using the same code and appending to the log. If a case still fails, **leave the failure in ANSWERS**, since an honest failure record is better than a fabricated answer. Make sure the folder still has ANSWER.md/REASONING.md stating what failed.
4. Verify:
   ```bash
   bash .claude/skills/submission-check/scripts/check.sh
   ```
   Every case folder must have both files. Spot-read 2-3 for formatting only, not content edits.
5. **By 16:55**, commit and push:
   ```bash
   git add ANSWERS && git commit -m "chore: reality test results" && git push
   git rev-parse HEAD
   ```
   Put the hash in `SUBMISSION.md` and on the form. Ask the user before pushing to `main` if that's the submission branch.

## After 17:00

The implementation and ANSWERS must not change. Only these may be added: the demo video (via Git LFS), the LinkedIn and X post URLs, and SUBMISSION.md metadata (team, track, members, hash, video path). Make sure the repo is **public**. Run `submission-check` one last time.
